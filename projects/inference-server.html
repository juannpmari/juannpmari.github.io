Inference Server — serving LLMs efficiently

A production-style LLM serving stack built around vLLM continuous batching, split into three services — a Gateway, a vLLM Engine and a Sidecar — with an OpenAI-compatible API, runtime LoRA hot-swapping, a 3-tier KV cache and full observability. Below are the benchmark results measured on Qwen2-0.5B on a single NVIDIA GPU.

📊Headline numbers

3,718peak throughput (tok/s) at N=256
10.8×throughput gain for 16× concurrency (313 → 3,371 tok/s, N=4→64)
91% / 40%N=64 sweet spot: 91% of peak throughput at 40% of peak latency
99.3%of end-to-end latency is decode (32→256 tokens); prefill TTFT ≈ 20ms
6.2×p99/p50 TTFT ratio at N=128 — overload canary
179msp99 TTFT at 50 RPS under Poisson load

📈Concurrency sweep

Throughput scales near-linearly with concurrency until the GPU saturates, while tail latency stays flat through the sweet spot and then climbs — the Pareto curve makes the optimal operating point explicit.

🧩Latency composition

Decomposing a 32→256-token request shows decode dominates end-to-end time (99.3%), with prefill (TTFT) at roughly 20ms — confirming that throughput optimizations should target the decode loop.

🌐Realistic (Poisson) load

Under a realistic Poisson arrival process throughput grows linearly up to ~10 RPS and saturates beyond ~30 RPS, with p99 TTFT held to 179ms at 50 RPS.

🏗️Architecture highlights

  • 3-service split

    Gateway, vLLM Engine and Sidecar, exposed through an OpenAI-compatible API with graceful, drain-aware shutdown.

  • Runtime LoRA hot-swap

    Adapters loaded and swapped at runtime with LRU eviction — no restart to switch fine-tunes.

  • 3-tier KV cache

    Prefix cache + L1 CPU (1024 × 128KB blocks over gRPC) + L2 Redis with consistent hashing.

  • Observability & deploy

    Kubernetes manifests with Prometheus / Grafana metrics for production-grade operation.
