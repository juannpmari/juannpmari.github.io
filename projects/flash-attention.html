Flash Attention — from scratch

A high-performance implementation of the Flash Attention algorithm in Triton, with both forward and backward passes and memory-access patterns optimized for modern GPUs. Attention is fundamentally memory-bound — naive implementations move O(N²) data between HBM and SRAM — and this kernel tackles that with tiling, kernel fusion and recomputation. Benchmarks below were run on a GeForce RTX 4050 (6GB), CUDA 13.0.

📊Headline numbers

3–5×faster than the naive implementation for sequence lengths > 1K
< O(N²)sub-quadratic memory-bandwidth scaling vs. naive attention
16×16default tile size, configurable for different GPU architectures
fwd + bwdboth passes implemented with full PyTorch autograd support

📈Benchmark plots

Both curves closely match the shapes reported in the original Flash Attention paper — confirming the expected latency and memory behaviour of the kernel.

⚡Core optimizations

  • Tiling

    Partitions Q, K, V into small tiles (default 16×16) that fit in SRAM, which requires an online (streaming) softmax to keep numerics correct across tiles.

  • Kernel fusion

    Fuses matmul, softmax and scaling into a single GPU kernel, minimizing round-trips between HBM and SRAM.

  • Recomputation

    Avoids materializing the O(N²) attention matrix by recomputing it during the backward pass — trading a little compute for a large memory saving.

🔍Key insights

  • Matches the paper

    Both the latency and memory curves reproduce the shapes from the original Flash Attention paper.

  • Sub-quadratic scaling

    Achieves better-than-O(N²) scaling for memory bandwidth as sequence length grows.

  • Real speedup

    3–5× faster than the naive implementation once sequence length exceeds ~1K tokens.
